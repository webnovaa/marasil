# برومبت دمج الحزمة داخل مشروع Expo

ادمج حزمة `marasil-expo-brand-kit` المرفقة في مشروع Expo الحالي. اقرأ README-AR.md أولًا، ثم افحص إصدار Expo وملف إعداد التطبيق ونظام التوجيه وطريقة إدارة مجلدي android/ios.

نفّذ الدمج محليًا، مع الحفاظ على التعديلات الموجودة وعلى هوية التطبيق: name وslug وandroid.package وios.bundleIdentifier وextra.eas.projectId وscheme والتوقيع والإضافات والصلاحيات ومتغيرات البيئة. لا تغيّر إعدادات API أو منطق واتساب أو الشاشات غير المتعلقة بالشعار.

انسخ assets/brand ومساعد config/with-marasil-branding.cjs. ادمج استدعاء المساعد في ملف الإعداد الفعلي بدل استبداله. إذا يوجد app.json فقط استخدم المثال الديناميكي المرفق مع إبقاء بيانات app.json. افحص أولوية ملفات الإعداد ولا تنشئ نسخًا متنافسة.

ثبّت expo-splash-screen باستخدام expo install إن لم يكن مثبتًا. اترك iosVariants معطّلًا إن لم تتأكد من توافق SDK؛ فعّله إن كان مدعومًا. فعّل خيار notifications فقط إذا التطبيق يستخدم الإشعارات أو المطلوب إعداد مظهرها، مع حفظ خيارات إضافتها الموجودة. لا تدّعِ أن تجهيز رمز الإشعار يجهز خدمة push.

استخدم المكوّن المرفق للشعار داخل الأماكن الموجودة المناسبة، واضبط مساراته. احتفظ بالملاحة وproviders والمصادقة. راجع إخفاء البداية إذا لدى التطبيق تحميل موارد؛ لا تضف تأخيرًا مصطنعًا أو انتظار شبكة غير محدود.

ادمج أصول الويب والـmanifest فقط إذا المشروع يستهدف الويب، مع احترام قاعدة المسار ووسوم HTML الحالية. لا تنشئ service worker ضمن مهمة الأيقونات.

تحقق من إعداد Expo النهائي والمسارات والأيقونات وتكرار الإضافات. إذا توجد native directories مُدارة يدويًا، طبّق طريقة المشروع المعتمدة ولا تستخدم prebuild --clean بلا مراجعة التعديلات. لا تنشر أو ترفع للمتاجر، ولا تبدأ بناءً سحابيًا مدفوعًا ضمن مهمة الدمج المحلي.

أعد تقريرًا عربيًا مختصرًا بالملفات المعدلة، الإعدادات المستخدمة، الفحوص المنفذة، وأوامر إنشاء preview/release مناسبة لهذا المشروع. ميّز فحص الأصول عن اختبار التطبيق على جهاز. لا تصف الملفات المكبرة بأنها متجهية أو ذات تفاصيل أصلية أعلى من المصدر 424×277.
