# مراسل — حزمة هوية Expo

حزمة أصول وإعدادات لدمج شعار مراسل في مشروع Expo موجود، وليست تطبيقًا كاملًا أو ربطًا بخدمات واتساب. افتح `START-HERE.html` لمعاينة الأيقونات وقراءة هذا الدليل بتنسيق عربي.

## 1. الجودة والهوية

المصدر المرفق صورة PNG شفافة بحجم **424×277** بكسل. احتفظنا بها كما هي داخل `source/marasil-logo-original.png`. الأصول الملونة مشتقة من الأصل دون إعادة رسم أو تغيير التدرجات. أزيل الهامش الشفاف الخارجي عند حساب التوسيط فقط؛ مساحة المحتوى 420×275.

ملف `source/logo-2048-upscaled.png` نسخة نقطية مكبرة إلى عرض 2048 بكسل، وليس SVG أو ملفًا متجهيًا أو تفاصيل أصلية جديدة. لا توجد في الحزمة نسخة AI معاد رسمها. للحصول على جودة أعلى فعلًا عند العرض الكبير يلزم ملف المصمم SVG/AI/PDF المتجهي أو PNG أصلي أكبر. أصول 1024 مناسبة للتجهيز والبناء، مع بقاء حدود جودة المصدر.

الأصول البيضاء والأحادية مشتقة من شفافية الأصل؛ لذلك تختفي تفاصيل التدرج والنقطة المندمجة مع جسم الشعار في هذه النسخ. هي بدائل وظيفية للإشعارات والثيمات، وليست بديلًا للنسخة الملونة في الاستخدام الرئيسي.

الألوان المساعدة المقترحة للحزمة: خلفية فاتحة `#FAF7FC`، خلفية داكنة `#211428`، بنفسجي للواجهة `#321D3C`، ولون إشعار `#65406F`. هذه قيم تنسيق مقترحة، وليست ادعاء بأنها أكواد الهوية الرسمية. ألوان الصورة الأصلية محفوظة.

## 3. تركيب الحزمة في مشروع موجود

نفّذ الخطوات من مجلد المشروع الذي يحتوي `package.json`، ولا تستبدل المشروع بمجلد الحزمة.

1. انسخ `assets/brand` إلى `assets/brand` في مشروعك.
2. انسخ `config/with-marasil-branding.cjs` إلى المسار نفسه داخل مشروعك.
3. ثبّت إضافة البداية بما يناسب إصدار Expo في مشروعك:

```bash
npx expo install expo-splash-screen
```

4. إذا كان مشروعك يستخدم **app.json فقط** ولا يوجد ملف إعداد ديناميكي: انسخ `config/app.config.example.js` إلى جذر المشروع باسم `app.config.js`. اترك `app.json` في مكانه؛ سيستقبل الملف الجديد إعداداته عبر `config`.
5. إذا لديك `app.config.js` أو `app.config.ts` بالفعل، لا تستبدله ولا تنشئ ملف إعداد منافسًا. استدعِ الدالة على الإعداد النهائي الذي يحسبه مشروعك:

```js
const { withMarasilBranding } = require('./config/with-marasil-branding.cjs');

module.exports = ({ config }) => {
  const existingConfig = {
    ...config,
    // احتفظ هنا بمنطق إعداد مشروعك الحالي ومتغيراته وإضافاته.
  };
  return withMarasilBranding(existingConfig);
};
```

الدالة تستقبل ExpoConfig مباشرة، دون غلاف `{ expo: ... }`. لا تغيّر اسم التطبيق أو slug أو package أو bundleIdentifier أو projectId أو إعدادات الشبكة والصلاحيات. تضبط حقول الأيقونات وfavicon وإضافة البداية فقط. تعدّل نسخة الإضافة الموجودة عوض إضافة نسخة ثانية، وترفض وجود إضافات مكررة لتجنب دمج غامض. تستبدل خلفية adaptive السابقة وحقول البداية المرتبطة بالعلامة، بما فيها تجاوزات Android وiOS، حتى لا تتغلب الإعدادات القديمة على الملفات الجديدة.

احتفظ بمعرّفات تطبيقك الحالية؛ تغييرها قد ينشئ تطبيقًا مختلفًا عن المنشور. لا تتضمن الحزمة معرّفات وهمية أو بيانات EAS لحساب آخر.

## 4. الوضع الداكن والأيقونات الملوّنة بالنظام

الإعداد الافتراضي يربط أيقونة PNG واحدة لـiOS للمحافظة على توافق أوسع. عند تأكدك أن إصدار Expo في المشروع يدعم كائن `ios.icon`، فعّل النسخ المرفقة:

```js
return withMarasilBranding(existingConfig, { iosVariants: true });
```

اختبر light / dark / tinted على جهاز ونظام يدعمان المظهر المطلوب. الحزمة لا تتضمن ملف Apple Icon Composer بصيغة `.icon`؛ هي حزمة PNG. [مرجع إعدادات Expo](https://docs.expo.dev/versions/latest/config/app/)

شاشة البداية الداكنة معدّة بخلفية `#211428` وشعار أبيض. ربط هذه الأصول لا يحوّل واجهات التطبيق نفسها إلى Dark Mode. إذا تريد متابعة إعداد الجهاز، ادمج `userInterfaceStyle: "automatic"` في إعدادك، وثبّت `expo-system-ui` عند الحاجة لدعم الإعداد على Android، مع تطبيق ألوان الوضعين في واجهاتك.

## 5. المساحات الآمنة وشاشة البداية

في Android وُضع الشعار بعرض 50% من طبقة adaptive، ويقع مستطيله بالكامل داخل الدائرة المركزية المحافظة ذات قطر 66/108 من مساحة الطبقة. الخلفية منفصلة، والنظام يتولى شكل القص؛ لا تقص الملف مسبقًا إلى دائرة أو مربع مستدير. نسخة maskable للويب لها هوامش مستقلة عن Android. [تصميم أيقونات Android](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)

إضافة البداية تستعمل `imageWidth: 240` و`resizeMode: "contain"`. الشعار داخل صورة البداية بعرض 60%؛ لذا عرضه المرئي الاسمي نحو 144 وحدة من صندوق بعرض 240، وقد تختلف قيود العرض بين الأنظمة. لا تستخدم صورة هاتف كاملة كأصل للبداية. المعاينة في الدليل توضيحية وليست لقطة من تطبيق مبني.

لا تضف تأخيرًا زمنيًا لمجرد إظهار اللوغو. الإخفاء التلقائي كافٍ إذا لا يوجد تحميل موارد خاص. إذا كان مشروعك يستعمل `preventAutoHideAsync()`، احتفظ بمسار `hideAsync()` عند جاهزية الموارد المحلية الضرورية، وحتى عند فشل تحميلها؛ لا تجعل البداية تنتظر اتصال API بلا نهاية. مثال Router المرفق مرجع بسيط، لا تستبدل به providers أو المصادقة أو التنقل الحالي. [مرجع SplashScreen](https://docs.expo.dev/versions/latest/sdk/splash-screen/)

## 6. الشعار داخل التطبيق

انسخ `examples/BrandLogo.tsx` إلى `components/BrandLogo.tsx` في الجذر. لو كان المشروع يستعمل `src/components` عدّل مسارات require إلى `../../assets/brand/...`.

```tsx
import { BrandLogo } from './components/BrandLogo';

<BrandLogo width={144} />
<BrandLogo width={144} tone="white" />
```

استخدم النسخة البيضاء على سطح داكن. المكوّن يحافظ على نسبة الشعار، ويضيف اسمًا لقارئ الشاشة؛ إذا توجد تسمية مجاورة تكرر المعنى، مرّر `decorative`. لا تعكس الشعار أفقيًا عند تفعيل RTL، ولا تستخدم `stretch` أو tintColor على النسخة الملونة.

## 7. الإشعارات — اختياري

إذا كان التطبيق يستخدم الإشعارات بالفعل أو ستضيفها:

```bash
npx expo install expo-notifications
```

ثم فعّل:

```js
return withMarasilBranding(existingConfig, {
  notifications: true,
  iosVariants: true // احذف هذا الخيار إن لم يدعمه إصدارك
});
```

هذا يضبط **مظهر الرمز فقط**. لا يفعّل إرسال push أو أذوناته أو قنوات Android أو FCM أو APNs. احتفظ بمنطق الإشعارات الحالي، ولا تنشئ اشتراكًا جديدًا بلا حاجة. الرمز 96×96 أبيض على شفافية حسب متطلبات الإضافة؛ استخدام اللوغو الملون كرمز صغير قد ينتج مظهرًا غير مناسب. [مرجع Notifications](https://docs.expo.dev/versions/latest/sdk/notifications/)

## 8. الويب — اختياري

الإعداد الأساسي يربط `web.favicon`. لباقي أصول الويب انسخ `public/brand` وادمج `public/manifest.webmanifest` دون الكتابة فوق manifest موجود. أضف الوسوم من `examples/web-head.html` إلى رأس HTML بالطريقة المناسبة لنظام توجيهك؛ في Expo Router يمكن دمجها في `app/+html.tsx` أو `src/app/+html.tsx` الموجود.

اسم manifest المقترح «مراسل»؛ عدّله إذا الاسم الرسمي مختلف. المسارات تبدأ من جذر النطاق؛ عدّل `scope` و`start_url` وروابط الصور والوسوم إذا كان النشر ضمن مسار فرعي. هذه أصول ويب وmanifest، وليست تنفيذًا للعمل دون إنترنت أو service worker.

## 9. البناء والتحقق على Windows

بعد الدمج افحص الإعداد، وراجع المسارات وإصدار SDK المستخدم:

```bash
npx expo config --type public
npx expo-doctor
```

يمكن تشغيل `npx expo start --clear` لمراجعة الشعار داخل الواجهات؛ لكنه لا يعيد بناء أيقونات النظام أو شاشة البداية. تغييرات الإضافات والأيقونات الأصلية تحتاج binary جديدًا؛ تحديث OTA وحده لا يكفي.

إذا تستعمل EAS: ادمج `config/eas.fragment.json` داخل `eas.json` مع الحفاظ على profiles ومتغيرات مشروعك. إذا profile باسم `brand-preview` موجود، اختر اسمًا آخر أو ادمجه عمدًا. مثال البناء:

```bash
npx eas-cli build --platform android --profile brand-preview
```

الحساب وإعداد مشروع EAS والتوقيع تُستخدم من مشروعك. للـiOS يمكن البناء سحابيًا من Windows بإعدادات Apple المناسبة؛ البناء المحلي لـiOS يحتاج macOS وXcode. ملف APK لا يُستخدم لـiOS.

إذا توجد مجلدات `android` و`ios` مُدارة يدويًا، تحقق من طريقة تطبيق config plugins قبل البناء؛ وجود إعداد Expo وحده لا يعني أن الملفات الأصلية ستتغير. لا تنفذ `prebuild --clean` على مشروع فيه تعديلات أصلية غير محفوظة.

اختبر البداية على preview أو release build، لأن Expo Go وdevelopment client لا يعكسان دائمًا المظهر النهائي. أغلق التطبيق وافتحه من الأيقونة. إذا بقيت أيقونة قديمة، تحقق أنك ثبّتت البناء الجديد ومعرّف التطبيق الصحيح؛ حذف التطبيق قد يمسح بياناته المحلية فلا تجعله أول خطوة. [دليل Expo للأيقونات والبداية](https://docs.expo.dev/develop/user-interface/splash-screen-and-app-icon/)

## 10. ما يجب مراجعته قبل النشر

- الأيقونة الرئيسية مربعة ومعتمة، ولا تقطع أطراف الشعار.
- adaptive يظهر جيدًا مع دائرة ومربع مستدير وفي الأيقونات ذات الثيم.
- البداية في الوضعين واضحة ولا تعلق عند انقطاع الإنترنت.
- الإشعار الصغير واضح، مع إدراك أن التدرجات لا تظهر في هذا النوع من الرموز.
- الشعار داخل الواجهة لا يتمدد أو ينعكس مع RTL.
- لا يوجد تكرار لإضافتي splash-screen وnotifications، والمسارات تطابق مكان الملفات.
- معرّفات التطبيق والتوقيع والصلاحيات والإعدادات الحالية محفوظة.

لم يتم بناء تطبيقك أو اختباره على جهاز، لأن مصدر مشروع Expo غير مرفق. جرى فحص مقاسات الصور وشفافيتها والمساحات الآمنة، وفحص سلوك مساعد دمج الإعدادات محليًا. اختلاف SDK أو native workflow قد يحتاج تعديل الدمج.

## 11. إعادة توليد المقاسات

اختياري للمطور: الحزمة تعمل دون تثبيت sharp. لإعادة توليد الصور فقط تحتاج Node.js وsharp؛ داخل نسخة منفصلة من الحزمة:

```bash
npm install --no-save --package-lock=false sharp
node scripts/generate-assets.cjs
```

السكربت يعيد كتابة الأصول المولدة ويحتفظ بالأصل. لا تغيّر المصدر إلى شعار بنسب مختلفة دون مراجعة هوامش الأيقونات ومكوّن العرض وملفات المعاينة. لا تحتاج إلى رفع صورة لأي خدمة لتشغيل السكربت.

المراجع راجعتها بتاريخ 12 أيلول 2026. لا تفترض أن `latest` يطابق إصدار مشروعك؛ اختر مرجع SDK الموافق له عند الدمج.
